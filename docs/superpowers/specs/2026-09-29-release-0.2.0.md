# NextRound 0.2.0 design

Scope: #37–#40 plus release validation #41, tracked by epic #42. The user authorized selecting scope, execution, merge and publication to GitHub and TestFlight.

Home is `/`; the existing builder moves to `/emom`. Session draft stays in Zustand. Header Home is disabled during active/paused workouts; existing navigation blocking stays authoritative. Completion provides Home as well as Repeat and Setup.

Settings is a centered modal with a macOS-inspired sidebar (Updates, About), grouped rows, a close button and keyboard/focus support. Uses existing Manrope type and charcoal/orange branding: #141414 canvas, #211f1d surface, #34312e dividers, #faf5ef text, #aaa49e secondary text, #ff5b0a actions. About presents version and release/support links. Updates contains persisted automatic checks and manual checking; no nonfunctional placeholders.

Splash replaces interactive shell during initialization, waits for the artwork to load, stays visible at least 3000ms, and also waits for initial session read. A ten-second readiness timeout shows retry UI rather than an indefinite splash. Image failure falls back to a branded textual splash. Browser tests use the same startup flow.

Updater uses Tauri's Rust updater with a NextRound public key and GitHub latest.json. Only direct-distribution builds compile the updater; App Store builds omit it via Cargo features. All update operations go through native commands. Installation reserves a native lock against workout start and rechecks active/paused sessions; UI blocks setup/start during install. Only success relaunches. Download progress and precise failures are surfaced. Checks have timeouts and automatic polling is infrequent (launch and six-hour intervals), with per-version dismissal. No automatic install.

Release packaging creates a tar.gz of the final notarized/stapled app, then signs those exact bytes; no later mutation. Feed validates version, architecture, signatures and artifact presence before publication. Preserve draft-then-publish workflow. 0.1.0 users must manually install 0.2.0 once.

Validation: failing-first browser/regression tests, native guard tests, feed validation tests; complete Makefile checks; native UI smoke; actual signed archive update/relaunch rehearsal; protected-main merge; both release pipelines; public checksum and Apple processing evidence.
