# NextRound 0.3.0 design

macOS Apple Silicon, minimum macOS 14. Ship through signed/notarized GitHub downloads and internal TestFlight. User authorized selecting and executing a focused feature/fix release. Version and Dock complaints are resolved by the user; no speculative changes for those.

## Close behavior
Native red-close defaults to minimize, including idle and active/paused workouts; minimizing does not stop or pause the workout. General Settings offers Minimize to Dock or Quit NextRound and persists it in the app configuration directory. Quit retains existing active/paused workout confirmation. Update installation prevents quitting. Dock activation restores the window. Handle close during startup natively, without granting webview destroy permissions.

## Countdown mode
Add a Home action and dedicated setup: duration in minutes/seconds (1–86400 total seconds), lead-in (0–3600 seconds), warning (0–59 seconds). One uninterrupted countdown; no minute-boundary beeps. Lead-in and final warning seconds use existing tocks, workout start beeps once, and completion uses the existing distinct sound. Zero lead-in starts immediately. Pause/resume, cancellation, full-screen display, sleep interruption, display-sleep prevention, Settings/update guards, completion, and repeat behave like EMOM. Preserve separate in-session setup drafts. Completion shows actual active duration, not fabricated rounds. No exercise list required for this mode.

Use a discriminated shared workout configuration with backward-compatible EMOM input. Mirror timing and cue rules in Rust and TypeScript and test boundaries. Native timer remains authoritative on macOS. Countdown integrates the current session/completion model; durable templates/results remain in #14/#17/#18, and are not release dependencies.

## Acceptance
Close/minimize/quit/reopen and preference restart persistence verified natively. Both timer modes retain correct cues and lifecycles. Browser/domain/native/release checks pass. Both direct-update and no-default-features store build commands succeed. PRs merge through protected main and merge queue. v0.3.0 GitHub assets verify, and TestFlight is VALID/in internal testing. Test upgrade from installed 0.2.0 using a separate test copy, preserving the user's installation and active sessions.

## Added exercise content (user steering)
Seed at least 20 kettlebell exercises, five additional variations each of push-ups/planks/squats, and rowing-machine rowing. Preserve existing IDs/default order. Research credible primary sources, write original concise form descriptions, and record sources. Test counts/uniqueness/text bounds and picker search/selection. Editable library/taxonomy remains outside scope.

## Per-exercise targets (user steering)
EMOM entries can optionally prescribe reps, seconds, metres or calories with positive whole-number values. Supported units vary by exercise; rowing supports seconds/metres/calories, push-ups support reps/seconds. Custom entries support all four. Show targets in setup and current/upcoming runner content; preserve them through reorder, repeat and immutable session snapshots. These are prescriptions within the fixed minute, not machine telemetry or new sub-round cue scheduling. Unknown units, unsupported combinations and out-of-range values are rejected by TypeScript and Rust.
