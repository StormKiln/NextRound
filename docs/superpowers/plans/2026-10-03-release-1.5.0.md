# NextRound 1.5.0 Implementation Plan

> Use superpowers:executing-plans inline, then one fresh whole-branch review.

**Goal:** Deliver equipment-aware selection, 20 catalog additions, AMRAP scrolling/error recovery and bounded notarization, then publish macOS1.5.0.
**Architecture:** Keep catalog metadata keyed by stable identity outside immutable workout snapshots. Store equipment preferences in a separate versioned on-device document; filter one eligible catalog shared by manual picking and suggestions. Keep native timer/storage interfaces unchanged. Use an external-process watchdog for notarytool rather than weakening signing gates.
**Stack:** Existing React/TypeScript/Zustand/TanStack/Tauri/Rust, Python release tooling.
**Spec:** Epic #105 and #98/#106/#107/#108/#94/#109. User explicitly authorized complete execution and publication.

## Constraints and decisions
- macOS only; one new feature,63 total catalog entries (43 retained+20 new). Balanced candidate slate in #106 is accepted by the execution request.
- No changes to existing IDs, user targets, history/template snapshots or usage attribution.
- Equipment metadata explicitly records all required items; a raised stable surface is required for incline/decline push-ups and Bulgarian split squats. Optional mats/floor space are not mandatory equipment. Single-dumbbell variants avoid ambiguous pair requirements.
- Unconfigured preferences show everything; configured empty shows known no-equipment only. Unknown requirements excluded under configured filtering, shown/labeled under override. Custom entries remain available and are never silently declared compatible.
- Override is picker-local, resets on closing; switching to Equipment settings preserves picker search, override and workout draft.
- Corrupt/unsupported preference storage is preserved and reported; no silent overwrite.
- Publication already authorized. Prior1.4 native checks remain separate; never claim locked-Mac observations passed.
