# NextRound 1.9.0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship personal exercises and three editing/search fixes to GitHub and Internal TestFlight.

**Architecture:** Personal exercise metadata lives in its own strict version-1 document. A merged library returns enriched selection records, but only existing ExerciseEntry snapshot fields cross into workout drafts/templates/results. Native stores serialize and atomically write; browser stores serialize mutations and normalize through JSON. Record IDs are client-generated personal UUIDs so retries are idempotent.

**Tech Stack:** Existing React, TanStack Query/router, TypeScript, Rust/Tauri and JSON repositories; no dependencies added.

**Spec:** GitHub epic #138 and linked #139, #137, #140, #141, #142.

## Global Constraints
- 103 bundled exercises remain read-only and unchanged. All six modes retain their contracts.
- Personal cap 500 including archived; names 1–120 and descriptions up to 2000 characters.
- Equipment/category/focus use existing taxonomy; no permanent intensity field.
- Namespaced IDs, duplicate names permitted, no retroactive attribution by name.
- Editing/archive affect future selections only; existing workout snapshots remain unchanged.
- Corrupt/future data preserved; failed reads disable personal writes while bundled choices remain usable.
- No new workout mode, sync/account, seeding or public App Store submission.

## Review Focus
- Saving a custom entry and retrying after a failed write must not create duplicates (Task 2/4).
- A reps-only personal entry without a default must never get a seconds target (Task 3/4).
- Hidden archived exercises must remain attributed in existing immutable history (Task 3).
- Competing edits must reject the stale expected record, preserving disk bytes (Task 2).
- Management returning to a picker must preserve the current draft and update metadata (Task 4).
