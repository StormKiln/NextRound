# NextRound 2.7.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver reusable workouts from session blocks, three replacement usability fixes, 20 exercises and verified macOS releases.
**Architecture:** Reuse the template repository for independent copies, leaving the session store untouched. Keep the save dialog isolated, reuse existing equipment settings and preserve replacement state across nested dialogs. Add catalog entries without changing earlier snapshots.
**Tech Stack:** React/TypeScript, Zustand, TanStack Query, Tauri/Rust, Vitest and Playwright.
**Spec:** https://github.com/StormKiln/NextRound/issues/388 and linked #389–395 (approved for execution).

## Global Constraints
Offline, account-free, macOS 14+, all six workout modes. Preserve existing local data, history, target semantics and Apple/GitHub updater separation. No dependency upgrades. Implementation issues close only after protected merge. Publication requires signed artifact and Apple-processing verification.

## Review Focus
- Delayed saves, duplicate submissions and cancellation must not produce duplicate workouts or false success (Task 1).
- Changed/removed source blocks and active workouts must not save an unreviewed configuration (Task 1).
- Duplicate labels must remain distinguishable without merging custom identities (Task 2).
- Settings nesting must preserve selection and support keyboard recovery after errors (Task 2).
- Long content, enlarged text and scrollbars must not hide actions (Tasks 1/2/4).
