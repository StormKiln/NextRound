# NextRound 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver complete offline training sessions, actual performance, safe backup/restore and the 2.0 release.

**Architecture:** Keep the six validated native workout engines and existing 1.x stores. Add a versioned training document and session orchestration with durable checkpoints, plus a journaled native restore transaction across existing stores. React/TanStack Query consumes validated repository interfaces; Zustand owns only transient orchestration and editing state.

**Tech Stack:** Existing Tauri/Rust, React/TypeScript, Zustand, TanStack, Vitest and Playwright.

**Spec:** docs/superpowers/specs/2026-10-17-release-200-design.md and GitHub #297–#308/#294.

## Global Constraints
- macOS 14+ Apple Silicon; offline/no account; preserve separate Apple/GitHub update channels.
- 1–20 ordered blocks; each embeds a validated configuration; unknown duration remains unknown.
- Recovery starts paused; never infer actual performance from targets or downtime.
- Existing files and historical identities survive; unsupported data fails without reset.
- Close implementation issues only on protected merge; record physical acceptance separately.

## Review Focus
- Crash between result persistence and checkpoint cleanup must not duplicate or lose results (tasks 1/3).
- A manual wait or uncapped block must not produce a misleading overall countdown (tasks 1/2).
- Partial restore and concurrent writes must leave a recoverable whole dataset (task 6).
- Repeated exercises and changed prescriptions must not produce misleading comparisons (task 4).
- Long content, keyboard focus and visible scrollbars must keep actions reachable (tasks 5/7).
