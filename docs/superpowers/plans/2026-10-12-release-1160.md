# NextRound 1.16.0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Track the checked steps and verification evidence in the release ledger.

**Goal:** Ship a filter-aware training summary and trustworthy history updates, then publish GitHub and TestFlight 1.16.0.

**Architecture:** Derive summary values from the exact filtered history array. Coordinate explicit history reads/writes around the shared QueryClient, retain native/browser optimistic deletion parity, and distinguish unknown/stale data from valid zero totals. Storage stays version 1.

**Tech Stack:** React, TypeScript, Zustand, TanStack Query, Rust/Tauri, Vitest and Playwright.

**Spec:** GitHub epic #210 and acceptance criteria #211–#215, explicitly authorized for execution by the user.

## Global constraints
- macOS 14+, Apple Silicon, all six existing workout modes; native minimum window 760×620.
- Local/offline records; no statistics persistence or schema migration. Preserve snapshots, notes, usage, templates, preferences and personal exercises.
- Saved sessions include time-capped outcomes. Workout time includes programmed rest, excludes lead-in/pause. Active days use local completion dates.
- Protected merge; immutable tag; signed GitHub and Apple-managed TestFlight channels.
- Earlier exact-version observations remain separate (#207).

## Review focus
- A pending read started during a mutation must not undo that mutation (task 2).
- Invalid custom date drafts must not recalculate the applied summary (task 3).
- Different JSON property ordering must not spuriously reject deletion (task 1).
- A read completion from an unmounted view must not cancel a new view's query (task 2).
- Tiny positive elapsed values and totals exceeding 24 hours must remain truthful (task 3).

## Task 2: Coordinate history cache updates (#213)
Files: new history/cache.ts + cache.test.ts; history/index.tsx, note-editor.tsx, result-actions.tsx and interaction tests.
Interface: `readHistoryIntoCache(client, active)` and `mutateHistoryIntoCache(client, mutation)` return validated HistoryDocument. Serialize explicit operations per QueryClient; cancel in-flight queries before and after successful operations. Read callbacks require active view; successful writes still publish after unmount.
- [ ] Add deferred read regressions for note save, refresh, deletion and unmount. Observe failures.
- [ ] Route explicit history reads/mutations through the shared coordinator. Keep query readers and existing note guards; do not turn a post-save refresh failure into failed persistence.
- [ ] Verify newer refetch still works, failed operations preserve cache, drafts survive conflicts and newer routes are not disturbed. Commit after tests pass.

## Task 3: Summary and honest data states (#211, #214)
Files: new history/summary.ts + summary.test.ts + training-summary.tsx; history/index.tsx/history.css; release-1160.spec.ts and interaction tests.
Interface: `summarizeHistory(results)` returns sessions, elapsedMs (bigint) and activeDays. `formatWorkoutTime(ms)` rounds the aggregate upward to whole seconds, preserving any positive duration; shows days/hours/minutes/seconds without wrapping.

- [ ] Add compact semantic definition list based on the same filtered array. Hide totals when data is unknown; label prior data after failed reads consistently with visible list. Valid empty data gets real zeros.
- [ ] Regress combined/applied-vs-draft filters, notes changing search membership, deletion, refresh, retry, focus and minimum size. Commit verified behavior.
