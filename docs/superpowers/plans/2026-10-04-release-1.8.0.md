**Goal:** Ship Ladder and scoped library/history/validation improvements as macOS1.8.0 on GitHub and TestFlight.
**Architecture:** Extend the existing tagged config and native session with Ladder progression; native snapshots own progress and timing. Use optimistic compare-and-update for templates. **Tech Stack:** React, TypeScript, Zustand, TanStack, Tauri/Rust, Vitest, Playwright.
**Spec:** docs/superpowers/specs/2026-10-04-release-1.8.0.md

## Global Constraints
- Six modes; existing103 exercises/snapshots unchanged; macOS only, minimum760×620.
- No new service/dependency, no silent unit conversion, no iOS/sync/old-release closure.
- Ladder uses one reps progression for all exercises; cap/lead/pauses match For Time. Last movement pauses for final confirmation; cancellation allows Undo or Finish again.
- Bounds: start/increment1–1000, rungs1–50 (pyramid up to99), exercises1–100, cap1–86400seconds. Preview exact targets and planned total without truncation.
- Issue updates throughout; close implementation after protected merge. Tag immutablev1.8.0; verify both artifacts and exact Apple Internal build.

## Review Focus
- Cap racing a final movement/Finish produces one cap result; no clock or progress drift on native/browser.
- Duplicate/failed controls and webview retry preserve native progress and result resolution.
- Template compare-and-update rejects stale/deleted source and retains draft/source identity across modes.
- Editing one invalid field does not hide another or leak errors to another mode; Save and Start focus the right invalid control.
- Filtered deletion targets stable result IDs and invalidates usage without rewriting history.
