# NextRound 1.18.0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship explicit exercise favourites, 20 new movements and library fixes as signed GitHub/TestFlight 1.18.0.
**Architecture:** Store favourite library IDs as validated versioned local preferences, using synchronous read-before-write and publish-after-success Zustand state. Keep history-ranked suggestions separate (`frequent`), and resolve true favourites before generation. Existing native workout/library documents and snapshots remain unchanged.
**Tech Stack:** React, TypeScript, Zustand, TanStack Query, Tauri/macOS, Vitest/Playwright.
**Spec:** Approved epic https://github.com/StormKiln/NextRound/issues/229 and linked acceptance #230/#231/#232/#233/#228/#234.

## Global Constraints
- macOS 14+, Apple Silicon; preserve six workout modes and separate distribution channels.
- Stable library IDs, no inferred stars, no personal-data loss on read/write failure.
- Preserve generation count choice, timing, Undo, equipment eligibility and reps-only Ladder.
- Keep canonical checkout unchanged; use protected merge queue and immutable release tag.

## Review Focus
- Invalid/future favourite documents and failed writes preserve bytes and do not change UI selection.
- Archived or unknown favourite IDs remain stored but are never generated; restoration recovers the star.
- History errors cannot block explicit favourites; favourite errors cannot corrupt history presets.
- Unstarring the final visible row and renaming filtered personal exercises restore stable focus.
- Too-small eligible favourite pools do not silently fill with nonfavourites.
